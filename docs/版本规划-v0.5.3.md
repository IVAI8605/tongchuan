# 通传 v0.5.3 · 版本规划（块大小 8 MiB）

- 制定：2026-11-12 10:55
- 上游：v0.5.2（2026-11-12 10:40 发版）
- 定位：**协议变更版**，块大小 4 MiB → 8 MiB；三端必须同批升级
- 结论标注：【实测】＝跑过；【推断】＝按机制推的，实施后复测

---

## 1. 为什么改

250 GB 设计量级下，块大小直接决定三件开销：

| 项 | 4 MiB | 8 MiB |
|---|---|---|
| 总块数（250 GB） | 约 59,600 | 约 29,800 |
| 位图行数（v0.5.2 起追加写） | 6 万行 | 3 万行 |
| 逐块往返/调度次数 | 6 万次 | 3 万次 |
| 接收端在途内存（预取窗口 4） | 16 MiB | 32 MiB |

v0.5.2 已把位图写入量降下来，但块数本身没变；块翻倍是「再降一半」的唯一办法。

代价要说清：单块失败的重传粒度从 4 MiB 变成 8 MiB；接收端常驻内存多 16 MiB。两者都在可接受范围（手机与 NAS 都不缺这 16 MiB）。

---

## 2. 协议影响（本版的核心风险）

块大小是**编译期常量**，帧头里没有这个字段。0.5.2 与 0.5.3 会被版本门禁判定为「同主次版本、可互通」，于是 4 MiB 与 8 MiB 混用会一路传到校验阶段才报块哈希不匹配——用户完全看不出原因。

修法（本版做）：

1. `HELLO` 增加 `blockSize`（`#[serde(default)]`，旧端反序列化为 0）。
2. `HELLO_ACK` 同样回带 `blockSize`，让新发送端也能拒绝旧接收端。
3. 接收端在**版本门禁之后、信任判定之前**比对：不一致回 `BUSY`，原因写明「本机 8 MiB 与对端 4 MiB 不一致，请把两端升级到同一版本」。
4. 发送端收到 `HELLO_ACK` 后同样比对，早停而不是传完再报错。

行为变化：**0.5.2 ↔ 0.5.3 不能互传**（旧端仍会放行新端，但新端会明确拒绝旧端）。发版说明与 CHANGELOG 必须写明「三端同批升级」。

## 3. 改动清单

| 文件 | 改动 |
|---|---|
| `crates/tc-core/src/frame.rs` | `BLOCK_SIZE` 4 MiB → 8 MiB，注释写明协议含义 |
| `crates/tc-core/src/store.rs` | 位图加头 `#tc-map v2 <块大小>`；无头/块大小不符的旧位图整份丢弃（防止按错误偏移续传） |
| `crates/tc-core/src/session.rs` | `Control::Hello` / `HelloAck` 增加 `blockSize`；两端各加一处比对与拒绝；`block_size_reject_reason()` 给出可读原因；发送端块缓冲提到循环外复用（8 MiB 每块重新分配会制造内存抖动） |
| `tests/concurrency.rs` | Hello 字面量补 `block_size`；新增 `mismatched_block_size_is_rejected_at_handshake` |
| `tests/trust_gate.rs` | 冒充旧端的 Hello / HelloAck 补 `block_size: 0` |

## 4. 验收

| 项 | 门槛 |
|---|---|
| 单测/集成 | `cargo test --workspace` 全过（新增块大小拒绝用例） |
| 门禁 | `scripts/verify.ps1` 8/8 PASS |
| 兼容 | 4 MiB 端接入 → 握手即回 `BUSY`，原因含 `block size` 与 `4 MiB` |
| 真机 | 手机 0.5.3 → NAS 0.5.3 发送 6.914 GB：`verdict=OK`、`verified=true`；端到端不慢于 v0.5.2（约 60 s 级） |
| 内存 | 接收端在途 32 MiB + 缓冲，NAS 与手机均无异常 |

## 5. 风险与回滚

| 风险 | 对策 |
|---|---|
| 三端漏升导致「传不了」 | 握手即拒 + 明确提示；发版说明置顶「三端同批升级」；NAS 与 APK 同步发布 |
| 8 MiB 单块在弱网下重传成本变高 | 预取窗口 4 仍在，丢一块只影响 8 MiB；若实测恶化，回退到 4 MiB 只需改一个常量并三端重发 |
| 接收端内存峰值上升 | 窗口 4 × 8 MiB = 32 MiB 在途；实测手机无异常即通过 |
| 旧 `.tcpart` 半成品 | 块号含义随块大小改变。位图加了头 `#tc-map v2 <块大小>`：**没有头的一律视为不可用**（v0.5.2 及更早的位图都没头），整份丢弃重传，绝不按旧块号续传——那样会写到错误偏移、损坏文件 |
