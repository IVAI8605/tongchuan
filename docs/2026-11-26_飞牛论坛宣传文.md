# 飞牛 NAS 上装个「通传」：手机照片视频直传 NAS，不走云端

> 一个局域网内的目录互传工具。手机、电脑、飞牛 NAS 在同一网段时直连互传整个文件夹，不经过任何云端或中继。

## 先说场景

手机相册满了，想倒到 NAS 里存着。常见办法要么传微信/网盘绕一圈，要么插数据线，要么开 SMB 慢慢拷。

「通传」想解决的就这一件事：**在同一个局域网里，把整个目录（含子目录、空目录、相对路径）直接送到另一台设备**。手机拍的照片、视频，电脑上的资料夹，往 NAS 一丢，完事。

全程点对点，TLS 1.3 加密，没有服务器中转，也不需要公网 IP。

## 它能干什么

- **整目录传输**：一次发多个目录，子目录结构和空目录都还原，不是一堆散文件。
- **加密 + 身份**：TLS 1.3，双方自签证书，靠证书指纹确认身份，不依赖 CA。
- **断点续传 + 校验**：按块记进度，断了只补缺的块；每个文件 BLAKE3 校验，传完验得过才算数。
- **同名不覆盖**：内容一样就跳过（增量），不一样就自动改名成 `名字 (1).扩展名`，老文件不丢。
- **自动发现**：`tc discover` 或手机 App 里直接列出同网段正在接收的设备，不用手输 IP。
- **离线队列**：对端暂时不在线，先入队，等它上线再 flush。
- **网页管理页**：daemon 自带一个网页，概览、发送、记录、安全、设置都在里面，密码登录。
- **小文件提速**：手机往 NAS 传大量照片的场景做过专门优化，单块小文件改为懒创建落盘。

实测数据（作者环境，千兆局域网）：800 MB 目录接收页显示约 110 MB/s；3000 张单块小图落盘速度提升约 25%。不同设备会有差异，仅供参考。

## 支持的设备

| 设备 | 形态 |
| --- | --- |
| 飞牛 fnOS / Linux / macOS | 命令行 `tc`；飞牛用 `.fpk` 应用包 |
| Windows | Tauri 2 桌面端（托盘 + 管理页窗口 + NSIS 安装包），也可单用 `tc.exe` |
| Android | App，常驻接收、发送、系统分享菜单、历史 |

## 在飞牛 NAS 上安装

1. 到 GitHub Release 下载 `tongchuan-1.3.3-linux-x64.fpk`：<https://github.com/IVAI8605/tongchuan/releases/tag/v1.3.3>
2. 飞牛网页版 → **应用中心 → 手动安装**，上传 fpk。
   - 第三方未签名 fpk 会提示「签名风险」，需要勾选确认才能继续（飞牛手机 App 里点确认仍会失败，用网页版）。
3. 安装向导里选**接收子目录**（默认「通传接收」）和**安全模式 / 宽松模式**：
   - **安全模式（默认）**：陌生设备第一次发文件，要在管理页生成二维码配对，或手动批准。推荐。
   - **宽松模式**：同网段发现即可传，只适合完全可信的自用环境。
4. 装好后打开应用，浏览器访问 `http://<NAS地址>:53319/`，**首次打开设置管理密码**，之后密码登录。
   - `/api/health` 是匿名的，方便体检；其它接口都要登录。

接收的文件落在应用自己的**共享文件夹 `tongchuan`** 下，文件管理器里能直接看到。应用以专用包用户运行，**不要 root 权限**；卸载不会删数据，身份、信任记录和已收文件都保留，重装接着用。

> 如果 NAS 上以前手工跑过旧版 `tc daemon`，先停掉它，占着 53318 / 53319 端口的话 fpk 起不来。想把旧设备的信任关系带过来，把旧 `identity/` 内容放到应用数据目录的 `.identity-import/`，首次启动会自动导入，不用重新配对。

## 手机端怎么用

1. 到 v1.3.1 Release 下载 `通传-1.3.1.apk` 安装：<https://github.com/IVAI8605/tongchuan/releases/tag/v1.3.1>
2. 打开 App，在「设置」里把**常驻接收**打开，并给足后台权限（不同机型保活设置不一样）。
3. 在「发送」页选好照片/目录，点「附近设备」找到 NAS；如果 NAS 是安全模式，先用右上角扫码图标跟管理页生成的二维码配对，或让 NAS 端批准一次。
4. 点「开始发送」，接收页能看到进度条和实时速度。

手机端还有系统**分享菜单**入口：相册里选好几张图，分享到通传，直接丢给 NAS。

## 安全和隐私这块

- 只监听局域网，不连外网、不上传任何文件，也没有中继服务器。
- 自签证书 + 指纹固定，第一次连接要人工确认指纹；不是随便一个同网段设备就能写盘。
- 接收落点有白名单，路径逐段清洗，`..`、绝对路径这类越界写法会被直接拒掉。
- fpk 默认 `trust_mode = closed`，未配对的设备发过来会被拒，文件不落盘（已实测）；管理页密码登录，会话用 HttpOnly Cookie。
- 应用不以 root 运行，不需要 plugdev 之类的额外授权。

一句话：**别把管理页暴露到公网**，局域网里用就够了。
