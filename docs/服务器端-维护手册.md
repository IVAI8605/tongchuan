> 本文面向无头服务器（NAS、家庭服务器）部署。开发过程的逐次记录已归入内部，仓库内只保留结论。

# 通传 · 服务器端部署与维护

## 1. 形态

服务器端跑的是同一个 `tc` 可执行文件，用 `tc daemon --config config.toml` 常驻：监听传输端口、可选管理页、可选剪贴板中继；数据（身份证书、信任表、历史、日志、队列）都落在配置里指定的目录。二进制本身不需要 root，也不需要写入自身所在目录。

## 2. 编译

在目标机同架构的 Linux 上原生编译最省事：

```bash
cargo build --release -p tongchuan
```

产物是 `target/release/tc`。跨平台交叉编译没有验证过，不保证可用。

发布构建建议同时启用 `strip` 与 `--remap-path-prefix`（见 `.cargo/config.example.toml` 的说明），否则 panic 信息里会带出构建机的源码绝对路径。四个平台的包尽量来自同一次同源构建，避免同版本出现两套不同产物。

## 3. 首次安装

1. 把 `tc` 与改好的 `config.toml` 放到同一个安装目录（示例模板见 `configs/config.example.toml`）。
2. 按 `configs/tongchuan.service` 装成 systemd 服务，改 `User`、`WorkingDirectory`、`ExecStart` 与 `ReadWritePaths`。
3. `systemctl daemon-reload` 后启动，确认 `/api/health` 返回 `ok`，日志出现「守护进程启动 <版本>」。

首次启动会在身份目录生成设备证书、私钥与管理页令牌，令牌文件权限为 0600。身份目录与信任表不要手工编辑，用 `tc trust` 或管理页维护。

## 4. 升级与回滚

1. 先备份配置、身份目录、队列与日志（只读复制即可）。
2. 停止服务，替换二进制，再启动。
3. 核对版本：`/api/status` 与启动日志里的版本号应一致；投递一次做端到端校验。

升级不涉及数据格式迁移，证书指纹、信任表与管理页令牌保持不变，已收文件无需重扫。回滚就是把备份的旧二进制换回来再重启。

## 5. 日常维护

- **日志**：按 `log_max_bytes` 自动轮转，归档只改名不删除；清理需要人工列清单确认。
- **历史**：发送与接收历史只追加不删行，界面按时间窗口过滤展示。
- **信任**：`tc trust list|pending|approve|revoke|rename` 与管理页读写同一份事件文件，撤销后下一场会话立即生效。
- **安全边界**：落点必须在 `allow` 白名单内；管理页只做令牌鉴权、不区分用户，不要直接暴露到公网。

## 6. 常见问题

- **启动失败、提示落点不在白名单**：`destination` 必须包含在 `allow` 内，这是防止任意写盘的保护。
- **端口被占用**：传输与发现共用 53318，管理页默认 53319，剪贴板默认 53320；同机起第二个实例会冲突，改用临时端口或停掉旧实例。
- **对端版本不兼容**：主次版本必须一致，升级时三端一起换。
- **第一个设备连不上**：信任模式默认 `closed`，需要先在接收端批准对端指纹。
