# 通传安卓端 UI 重构设计（2026-11-19）

> 状态：**待用户批准**。批准前不写产品代码。
> 范围：只改 Android 客户端界面层；传输协议、服务端（Rust/JNI/Windows/NAS）不动。

## 0 结论

安卓端从「Java + View 体系、颜色硬编码」整体迁到 **Kotlin + Jetpack Compose + Material 3**，
主界面重排为底部导航的三页结构，颜色/字号/形状全部走 `ui/theme/` 令牌；
版本号按用户要求 **大版本 +1：`0.20.1` → `1.0.0`**。

## 1 现状（实测）

- `app/src/main/java/com/tongchuan/MainActivity.java` **2325 行**：一个长滚动页塞了
  标题、发送卡、设备面板、剪贴板面板、最近接收、发送历史、状态、版本；UI 全部代码构建。
- `ScanActivity.java` **514 行**：Camera2 预览 + zxing 解码，UI 也是代码构建。
- 主题 `@android:style/Theme.DeviceDefault.DayNight`；7 个颜色常量硬编码在 Java 里
  （主色墨绿 `#1F6F5C`、底 `#F4F5F3`、卡 `#FFFFFF`、墨 `#1B1B1B`、弱 `#6B6B6B`、
  成功 `#2E7D32`、警告 `#9A5B23`、错误 `#B3261E`）。
- 无 Kotlin、无 Compose。AGP 8.7.3、compileSdk 35、JDK17、minSdk 26、只出 arm64。
- 依赖只有一个 `com.google.zxing:core:3.5.3`。
- 业务逻辑（服务启停、权限流程、发现/信任、JNI 调用、Intent 结果、剪贴板）与 View 字段
  深度交织，这是本次重构的主要风险来源。

## 2 目标与明确不做

**目标**
- 界面成体系：M3 组件 + 统一令牌，深浅色一套 scheme。
- 信息架构更清楚：底部导航分页，不再是一条长滚动。
- 无障碍底线：可点区域 ≥48dp、图标有 `contentDescription`、对比度达标。
- 每页有 `@Preview`，构建通过、真机可用。

**不做（本版明确排除）**
- 不改传输协议（协议号仍 `0.20`），不动 Rust/JNI/`libtc_jni.so`。
- 不动 Service / Receiver / `Dest` / `SendLog` / `TcNative` / `FileServeProvider` 的行为。
- 不改接收目录、数据位置、包名、签名方式。
- 不动 Windows / NAS 代码（只随 `Cargo.toml` 版本号变化）。
- 不引第三方 UI 库，不手搓第二套设计系统。

## 3. 信息架构（用户 2026-11-19 选定：四页）

主界面从「长滚动」改为 `Scaffold + TopAppBar + NavigationBar` **四页**：

| 页签 | 内容 |
|---|---|
| **发送** | 目标设备（多选）、落点、选择文件/目录、扫码配对、发送按钮、进度、发送历史 |
| **设备** | 常驻接收开关、接收目录、发现附近设备、信任列表、配对二维码、本机指纹、权限与保活入口 |
| **剪贴板** | 同步开关、剪贴板端口、立即推送、说明文字 |
| **接收** | 最近接收列表（点开文件、清理入口） |

- 「最近接收」单独成页，发送页只保留发送相关；原「设备与保活」折叠面板展开成独立一页。
- 页签多一个的代价接受，换来每页都短。
- 顶部 `TopAppBar` 放标题 + 常驻状态点；版本号放设置/关于（`TopAppBar` 溢出菜单或设备页底部）。
- 对话框（配对二维码、落点选择、目标多选）改用 M3 `AlertDialog` / `ModalBottomSheet`。

`ScanActivity` 保留 Camera2 预览与 zxing 解码，界面改 Compose：
预览用 `AndroidView` 包 `TextureView`，顶部 M3 `TopAppBar`，底部按钮与提示用 M3 组件。

## 4. 主题与令牌

- 新增 `app/src/main/java/com/tongchuan/ui/theme/`：`Color.kt` / `Type.kt` / `Shape.kt` / `Theme.kt`。
- 主色沿用墨绿 `#1F6F5C`，按 Material 3 色调板规则生成 light/dark 两套 `ColorScheme`
  （primary / onPrimary / primaryContainer / secondary / surface / surfaceVariant / error 等），
  不裸写十六进制、不随手 dp。
- 排版用 M3 `Typography` 默认阶梯（display/headline/title/body/label），不自定义一堆字号。
- 形状用 M3 默认（extraSmall→large），圆角只在卡片层出现。
- 动态取色（`dynamicColor`）**默认关闭**，保证品牌一致；代码里留开关。
- 现有 7 个硬编码颜色全部收敛进口袋：`COLOR_OK/WARN/ERR` 映射到 `primary`/`tertiary`/`error`
  语义槽（保留原有色相，避免成功/警告/错误分不清）。

## 5. 依赖与构建

**新增依赖**（全部 Apache-2.0，无 GPL 风险）：

| 依赖 | 版本 | 用途 |
|---|---|---|
| `org.jetbrains.kotlin.android` + `kotlin.plugin.compose` | 2.0.21 | Kotlin 与 Compose 编译器 |
| `androidx.compose:compose-bom` | 2024.12.01 | 统一 Compose 版本 |
| `androidx.compose.material3:material3` | BOM | M3 组件 |
| `androidx.compose.ui:ui` / `ui-graphics` / `ui-tooling-preview` | BOM | 基础 |
| `androidx.activity:activity-compose` | 1.9.3 | `setContent` |
| `androidx.lifecycle:lifecycle-runtime-compose` | BOM 附近 | `collectAsStateWithLifecycle` |
| `androidx.core:core-ktx` | 缓存已有 | Kotlin 扩展 |

保留 `com.google.zxing:core:3.5.3`。

**构建环境**（实测）：
- 本机 `gradle` 8.11.1、JDK17、SDK platform 35 / build-tools 36.0.0 都在。
- 共享缓存 `_tool/gradle-cache` 在本机 **不可初始化 native services**（PartZ 已踩过），
  所以用项目内可写缓存 `src/cache/gradle-home`，并借 `GRADLE_RO_DEP_CACHE` 复用
  PartZ 的 `cache/gradle-home`（Compose BOM 2024.12.01 + material3 1.3.1 + activity-compose 1.9.3
  + Kotlin 2.0.21 + AGP 8.7.3 都在那里），缺的再从 aliyun 镜像补。
- `settings.gradle.kts` 加 aliyun 镜像（`dl.google.com` 本机不通，aliyun 实测 200）。

## 6. 迁移策略与分批（每批可编译）

1. **骨架**：加 Kotlin/Compose 插件与依赖、`ui/theme/`、`MainActivity` 换成空壳 Compose 宿主，
   先让构建通过（业务暂不接）。
2. **发送页**：状态桥 + 目标/落点/选文件/发送/进度/历史/最近接收。
3. **设备页**：常驻、目录、发现、信任、配对二维码、指纹、权限入口。
4. **剪贴板页** + 顶部导航/状态点/关于。
5. **ScanActivity** 界面 Compose 化（预览逻辑不动）。
6. 收尾：删旧 View 代码、`strings.xml` 收敛、`@Preview`、无障碍检查。

业务逻辑（JNI/服务/权限/Intent）在迁移中保持语义不变；发现/信任/发送状态用
`StateFlow` + `collectAsStateWithLifecycle` 暴露给 Compose。

## 7. 版本

- `Cargo.toml` 的 `workspace.package.version`：`0.20.1` → **`1.0.0`**（唯一来源）。
- Android `versionCode` 由 `1*10000+0*100+0 = 10000`（现 2001，单调递增），`versionName` 读 Cargo。
- **协议号不动**（仍 `0.20`）：本次只改界面，不改协议；否则 Windows/NAS 旧端会不互通。
- Windows / NAS 下次构建自动跟到 `1.0.0`（同一 Cargo.toml）；本轮只构建 Android。
- 状态卡「三端版本支持表」同步更新。

## 9. 风险

- **逻辑与 UI 交织**：迁移中漏改状态推送会导致界面不更新 → 用「每批只搬一块、每批真机点一遍」控制。
- **依赖下载**：`dl.google.com` 不通，必须走 aliyun；缺包时构建失败而非静默。
- **Compose 包体变大**：只出 arm64、不开混淆，体积增幅可接受。
- **回归面**：权限/服务/通知在 Android 15 上有额外限制，真机验证为准。
