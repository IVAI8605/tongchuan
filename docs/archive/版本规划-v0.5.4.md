## 1. 要解决什么

| 现状痛点 | 依据 |
|---|---|
| 手机被 NAS 拒绝时，界面只有一段英文 JSON（`untrusted <指纹>`），用户不知道该去哪批准、拿什么去批准 | 现有代码 `startSend()` 直接把 reason 塞进 TextView |
| core 早已支持 `pair_code`，但手机侧没有输入入口，只能去 NAS 管理页批准 | `sendJson` 的 pairCode 参数一直传空串 |
| 发送跑在 Activity 的线程里，界面退到后台/熄屏随时可能被系统回收 | `startSend()` 里 `new Thread(...)` |

---

## 2. 改动

### M4 拒绝与配对体验

1. **原因翻译**（`MainActivity.friendlyFailure`）：把内核原因分成四类，每类给「怎么了 + 下一步」：
   - `untrusted` → 对方未信任本机 + 本机指纹 + 去管理页批准 / 填配对码
   - `pair code mismatch` → 配对码不对
   - `block size mismatch` / `version mismatch` → 两端版本不一致，三端同升
   - `os error` / `timed out` / `connection` / `reset` → 连接中断，检查对方是否在接收
2. **配对码输入框**：发送区新增，只接受数字；发送时透传给 `sendJson`。
3. **本机指纹常驻显示**：`tc-jni` 的信任快照增加 `selfFp` 字段，界面在「选择文件夹」下方显示前 8 位。
   （不改协议，只是把已有身份读出来。）

### M5 锁屏后台发送

1. 新增 `SendService`（前台服务，`connectedDevice` 类型，与接收服务同类型）：
   - 通知实时显示「已发送 N% / 速率」
   - 持 `PARTIAL_WAKE_LOCK`（上限 6 小时），熄屏不中断
   - 网络类失败自动重试 1 次（`os error` / `timeout` / `connection` / `reset`），其余不重试
   - 结果写进程内静态字段，Activity 轮询取走
2. `MainActivity.startSend()` 改为提交给服务；界面线程只做进度刷新与结果展示。
3. 同一时间只允许一批发送（服务内 `running` 互斥），避免进度快照互相覆盖。

## 3. 验收

| 项 | 断言 |
|---|---|
| 拒绝提示 | 在 NAS 上 `tc trust revoke` 掉手机 → 手机发送 → 界面出现「对方还没有信任这台手机」+ 本机指纹 + 下一步 |
| 配对码 | 填对配对码重发 → `verdict=OK`，NAS 信任表恢复该设备 |
| 锁屏发送 | 开始发送 1 GB 后立即灭屏，等 3 分钟 → 文件完整、`verified=true` |
| 通知 | 发送期间通知栏显示进度，结束后自动消失 |
| 兼容 | 0.5.3 ↔ 0.5.4 可互传（协议未改） |
| 门禁 | `scripts/verify.ps1` 8/8 PASS |

## 4. 风险

| 风险 | 对策 |
|---|---|
| Android 14+ 前台服务类型限制 | 复用接收服务已通过的 `connectedDevice` 类型与权限 |
| 服务启动失败（无通知权限） | 启动前调用 `ensureNotificationPermission()`；界面 3 秒内拿不到结果即报「服务未能启动」 |
| 结果静态字段跨进程丢失 | 服务与 Activity 同进程；`android:process` 未另开，成立 |
| 重试把「未信任」也重发一遍 | 只对四类网络错误重试，其余原样返回 |
