# v0.14 海量小文件 pack 流：协议设计

> 目标：10 万级小文件不再被「每个文件一次请求-响应」压垮。
> 状态：设计稿（2026-11-15），实现时以本文件为准；与代码冲突时先改本文件再改代码。

## 1 现状与瓶颈

- 接收端从清单里收集所有缺失块，逐块发 `BlockReq`，维护 4 个在途请求（`session.rs` 的 `inflight`）。
- 每个小文件通常只有 1 块，于是**每个文件都要一次 `BlockReq → BlockData` 往返**。
- 局域网 RTT 约 3–17 ms，10 万文件光往返就要数百秒；带宽完全没吃满。
- 大文件已经受益于 4 窗口流水线，小文件没有。

## 2 方案：批量块请求（pack）

不新增数据格式，只把「请求的粒度」变粗：

1. 接收端把待传块切成若干 **pack**（每包最多 N 块 / 最多 M 字节）。
2. 每个 pack 发一个 `PackReq` 帧，payload 是块列表（JSON）。
3. 发送端按列表顺序连续回 N 个现有的 `BlockData` 帧（帧头本来就带 `file_id` 与 `block_index`）。
4. 接收端连续读 N 帧、逐块落盘、逐块喂增量校验，与现在完全一致。

关键点：**`BlockData` 格式不变**，落盘、位图、续传、增量校验、根哈希都不动，改动集中在收发两处的循环。

### 2.1 帧定义

`FrameType` 新增：

| 值 | 名称 | file_id | block_index | payload |
|---|---|---|---|---|
| 5 | `PackReq` | 0 | 0 | JSON：`{"blocks":[[fileId,blockIndex],...]}` |

- `fileId` 是会话内文件序号（与 `BlockData` 帧里的含义一致）。
- 单个 pack 的块数上限 256、字节上限 64 MiB（按清单里每块的预期大小累加）；两者先到先停。
- payload 走现有帧长校验（`BLOCK_SIZE + 1024`），256 个块的 JSON 约 5 KB，远低于上限。

### 2.2 发送端

- 收到 `PackReq` 后解析块列表，逐个 seek + 读块 + 发 `BlockData`。
- 复用现有 `handles`（文件句柄 LRU）与 `block_buf`，不额外分配。
- 进度回调按块累计，与现在一致；`current` 取该块所属文件的 `rel_path`。
- 收到未知/越权文件（不在 `accepted_file_ids`）仍按现有规则报错。

### 2.3 接收端

- 构造请求时不再逐块 push，而是按「文件顺序 + 块顺序」切包。
- 一个 pack 发完再读它的 N 个 `BlockData`；对 pack 维持 **2 个在途**（而不是 4 个块），进一步省往返。
- 读到的每帧仍要校验 `file_id/block_index` 与请求一致，防止错位。
- `max_blocks`（模拟中断）模式退回逐块路径，保证「中断后续传」的测试语义不变。

## 3 兼容：能力协商

新增帧类型对旧端是硬错误（`unknown frame type`），因此必须协商，不能默认开：

- `Control::Hello` 与 `HelloAck` 各加一个字段：
  ```json
  "caps": ["pack"]
  ```
  `#[serde(default)]`，旧端反序列化为空表。
- 只有 **双方都声明 `pack`** 时，接收端才发 `PackReq`；否则走现有逐块路径。
- 结果：0.13 与 0.14 仍能互传，只是 0.14↔0.14 才享受 pack；不需要为兼容升主版本。

## 4 不改的东西（明确边界）

- 清单（`Manifest`）结构与哈希算法不变。
- `.tcpart` 位图、断点续传、同名让位、强制重传、增量跳过都不变。
- 块大小仍是 8 MiB 编译期常量。
- 不做并发连接（那是 v0.15）。

## 5 验收口径

1. **功能**：同一批小文件分别用旧路径与 pack 路径发送，接收端目录树、文件内容、`verified=true` 一致。
2. **性能**：1 万个 4 KiB 小文件（约 40 MiB），pack 路径的端到端时间应显著低于逐块路径；记录两者数字，写进 CHANGELOG。
3. **兼容**：用一个只声明空 caps 的模拟对端（现有逐块逻辑）跑一遍，确认自动降级、不报 `unknown frame type`。
4. **中断续传**：pack 路径中途取消，`.tcpart` 位图正确，续传只补缺口。
5. **门禁**：`verify.ps1` 8 项全过；新增 pack 相关单测与 e2e。

## 6 实施顺序

1. `frame.rs`：`PackReq` 帧类型 + 编解码测试。
2. `session.rs`：`Control::Hello/HelloAck` 增 `caps`，双方握手记录 `peer_caps`。
3. 发送端：处理 `PackReq`（可先在测试里手工构造）。
4. 接收端：切包 + 发 `PackReq` + 连续收；`max_blocks` 模式保留旧路径。
5. 单测 / e2e / 性能对比；三端同升 0.14.0。
