## 5 接口与口径设计（本版的关键决定）

### 5.1 数据字段（只加不改，保持旧字段语义）

**`ReceiverReport`**（`session.rs`，约 474 行）新增两个字段：
- `wall_us: u64` — 会话墙钟，从「首块请求发出」到「末块落盘」的实耗微秒（不含握手与清单，跟现有实测口径一致）。
- `avg_bps: u64` — `bytes * 1_000_000 / wall_us`，墙钟均速（字节/秒）。

**四段耗时 `wait_us/write_us/req_us/verify_us` 原样保留**，不改语义、不改单位，避免历史日志无法对照。

**`SendReport`**（`session.rs`，约 454 行）新增：
- `wall_us: u64`、`avg_bps: u64` — 同上，覆盖发送整个数据阶段。
- 发送端分段耗时：`scan_us`（清单扫描）、`data_us`（数据收发）、`verify_us`（等接收端裁决）。

### 5.2 日志新增字段（本地字符串，不进协议）

- 接收结束行末尾追加：`墙钟=<X>ms 均速=<Y>MiB/s 等数据速=<Y> 写盘速=<Y> 发请求速=<Y> 校验速=<Y>`。
- 发送 `SEND` 行末尾追加：`墙钟=<X>ms 均速=<Y>MiB/s 扫描速=<Y> 数据速=<Y>`。
- **分段等效速率的口径必须随日志写明**：`段速 = bytes / 段耗时`，是「多流累计口径」，4 流时会虚高，只用于同一配置下纵向对比；**真实速度以「均速」（墙钟）为准**。
- 零耗时（如 `skipped` 全部跳过）时打印 `n/a`，不打印 0 或除零。

### 5.3 Android 接收页实时速度（不改协议）

- 接收侧新增一个全局进度快照，字段对齐发送侧 `SendProgress`：`bytes_received`、`total_bytes`、`blocks_received`、`speed_bps`、`receiving: bool`。
- `TcNative` 新增 `public static native String recvProgress();`，JNI 侧读取该快照返回 JSON。
- `TcController` 新增轮询线程（约 1 秒，与发送进度同频），写 `UiState` 的 `recvProgress`/`recvSpeedText`/`recvReceiving`。
- `ui/ReceiveScreen.kt` 在「最近一次接收」上方插入一块：接收中显示 `LinearProgressIndicator` + `已收/总量 · X.X MB/s`，非接收时不显示。
- 接收完成保留 `lastRecvText` 摘要，追加本次均速一句。

### 5.4 手机侧操作记录（本版新增第 ④ 项）

**目标**：AI 经 ADB 能拿到「某时刻做了什么操作、结果如何、慢在哪」，且不依赖会被冲走的 logcat。

**写入位置**：应用私有目录 `files/ops-log.jsonl`，追加写，单行 JSON。理由：`send-history.jsonl` 已在此目录，权限模型一致；不写 `/sdcard` 避免被用户/清理工具误删。

**记录字段**（只记动作与度量，不记路径/文件名/内容，符合规范 #14 与 `SendLog` 的脱敏约定）：
- `ts`（ Unix 秒）、`op`（操作类型）、`ok`（bool）、`reason`（失败原因，脱敏）、
- 度量字段按 op 选填：`files`/`bytes`/`wall_ms`/`avg_bps`/`stage_*_ms`、`peer`（目标名或地址）、`dest`（落点根目录名）。
- `op` 枚举（第一版至少覆盖这些）：`send_start`、`send_done`、`recv_done`、`pair_ok`、`pair_fail`、`trust_approve`、`probe_result`。

**挂钩点（关键：覆盖所有触发路径）**：
- 发送结果：`SendService` 拿到结果后写一条 `send_done`（而不是只写在 `TcController.parseOutcome`）——这样 UI 点击和 `tc_cmd=send` 探针两条路径都会落盘，堵住 11-21 那次的缺口。
- 发送开始：`SendService.start()` 写 `send_start`。
- 探针结果：handleProbe 的 `tc_cmd` 分支末尾统一写 `probe_result`（含 cmd 与 ok）。
- 接收完成：daemon 回调进 JNI 时写 `recv_done`。
- 配对/信任：`pair` 与 `trust approve` 的现有回调各写一条。

**取回命令（写进状态卡，AI 无人工介入可跑）**：
- App 侧新增 `tc_cmd dump-log` 探针：把 `ops-log.jsonl` 拷贝到 `/sdcard/Download/tongchuan-ops-log.jsonl`，返回 `{"ok":true,"path":...}`。
- AI 侧：`adb shell am start -S -n com.tongchuan/.MainActivity --es tc_cmd dump-log` 等结果，再 `adb pull /sdcard/Download/tongchuan-ops-log.jsonl <本地路径>`。
- 注意：生产包不能 root、`run-as` 报 not debuggable，所以必须走「App 自己拷到公共目录」这条路，直接 cat 私有目录不可行（2026-11-23 实测）。

**logcat 节流**：`TONGCHUAN-PROBE` 的 PROGRESS 由每 250 ms 一条改为「状态变化时才打」或降到 ≥1 s，避免自己冲掉 buffer；详细进度留给 `ops-log.jsonl` 与 UI。

**轮转**：单文件超 4 MiB 时把当前文件改名为 `ops-log-<时间戳>.jsonl` 后新建，旧文件保留不删（规范 #11 轮转需可执行验证：造够量触发一次，检查文件数与大小）。

## 8 风险与边界

- 墙钟起点若选在 HELLO 会包含握手/清单，与现行实测口径不一致；必须在任务 1 单测里钉住「首块请求到末块落盘」。
- 多流分段累加不得当作真实速度；日志文案必须带口径说明，否则会被误读成吞吐。
- 只加字段不改协议；`PROTOCOL_VERSION` 保持 `0.20`，不触发三端门禁。
- 不新增报告页面、不做日志查看 UI（规范 #16）；速度只进现有日志行与现有接收页，操作记录只进文件 + ADB 取回。
- 操作记录不得写路径、文件名、文件内容、令牌/指纹原文（规范 #14）；只记动作、计数、时长、结果。
- 探针 PROGRESS 节流不能影响真实进度显示与 UI 轮询；详细进度进 ops-log，logcat 只留状态变化。
- 改代码前先建可恢复点；产物走 `_外置/产物/<项目>/release-v1.1.0/` 并配 `.sha256`。
