# 通传 AI-first CLI（v1.4.0）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `tc` 升级成 AI 可稳定操控的 CLI：JSON 输出、schema 自发现、退出码可判，同时保持现有脚本契约不变。

**Architecture:** 在 `src/src/main.rs` 之外新增 `src/src/cli/` 模块：spec（命令定义表，唯一事实源）→ parse（解析与校验）→ output（text 兼容 / JSON 双路）→ exit（错误分类与退出码）。业务仍全部下沉 `tc-core`，CLI 层只做解析、分发、格式化、选码。

**Tech Stack:** Rust 2021、tc-core（已有 serde/serde_json）、零新增第三方依赖（JSON 用 tc-core 已带的 serde_json）。

**Spec:** `docs/2026-11-26_CLI规范化设计方案.md` + 本轮用户约束（AI 便利、功能完整、升版、本地提交）

**可恢复点:** `_外置/备份/AI-CLI开工前_20261126-1931/`（main.rs / Cargo.toml / Cargo.lock / git-head / git-status，哈希已核对）

## Global Constraints

- 版本号唯一来源：`Cargo.toml` 的 `workspace.package.version`，本次 `1.3.3` → `1.4.0`（新功能升 Y，规范 #53）。
- 传输协议保持 `0.20` 不变（`crates/tc-core/src/session.rs:29`），本次不动协议、不动三端同步（CLI 是单端改动，按项目 `AGENTS.md:15-16` 不强制三端重编）。
- 默认输出（无 `--json`）必须与现状**逐字一致**：`SEND`/`RECV`/`TRUST`/`HISTORY` 等前缀与末位字段位置不变。
- 输出不得含私钥、管理口令、明文配对码；`tc diag` 既有脱敏规则保持。
- 构建：`CARGO_TARGET_DIR` 纯 ASCII + `TMPDIR` 指向构建缓存；不 push、不打 tag、不建 Release，只本地提交。
- Rust 测试：`cargo test --workspace` 全绿才算完成；门禁 `pwsh -NoProfile -File scripts/verify.ps1`。

## Review Focus

- **AI 解析 JSON 时字段名/类型漂移**：每个 JSON event 必须有稳定 `kind` 字段和固定键名，测试逐字段断言。
- **输出契约被破坏**：任何现有命令的默认输出变化都会打断脚本与 Android/Windows 壳，golden 断言逐字比对。
- **裸 `tc` / 未知命令静默 exit 0**：AI 无法判断命令失败，必须改成非 0 且不改变合法调用。
- **错误码混在 exit 1**：AI 无法区分「用法错/被拒/配置错」，严格模式下分类，默认模式不变。
- **凭据泄露到 JSON**：`--json` 模式不得输出 `identity.key`、管理口令、配对码；diag 输出必须脱敏。
