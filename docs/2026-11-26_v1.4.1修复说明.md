> 结论先行：五项需求全部落地，协议未动（仍 `0.20`，与 1.4.0 各端互通）。核心测试 167→170 项全绿，`scripts/verify.ps1` 9/9 PASS；Windows 桌面壳在**本机 GNU 工具链**下实测 `cargo check` 与 `tauri build` 成功并出 NSIS 安装包；Android APK 与飞牛 fpk 均按 1.4.1 重新构建。

## 1 五项需求与实现

| # | 需求（用户原话） | 实现 | 关键文件 |
|---|---|---|---|
| 1 | NAS 硬盘休眠时发送策略要优化 | ① 发送前对源盘并行**预热**：后台线程读每个源的头 2 个文件（4 KiB），把多块盘的起转时间重叠，最多 8 个文件；② 读块遇瞬时错误（盘刚醒的 EIO/未就绪）**退避重试 4 次**（0.5s→1.5s→4.5s→5s），重试前丢弃句柄重新 `open`；文件不存在/无权限立刻失败 | `crates/tc-core/src/session.rs`（`prewarm_sources` / `read_block_with_retry` / `HandleCache::invalidate`） |
| 2a | 电脑收到文件右下角短暂提示、点一下打开落点文件夹 | 新增无边框置顶提示窗（360×104，不占任务栏、不抢焦点），显示「收到 N 个文件 · 大小 · 来源」；5 秒自动收起（新文件到来重置计时）；点击用资源管理器打开**本次实际落点**；落点来自 `history.jsonl` 的 `roots` + config 的 `destination` | `windows-gui/src-tauri/src/main.rs`（`show_toast`/`watch_received`/`open_toast`）、`windows-gui/web/toast.html` |
| 2b | 支持文件拖动添加发送 | 窗口接收系统拖放 → 注入 `window.tcDrop(paths)` → 管理页「拖入的路径」列表可增删，与输入框路径合并成**一次会话**发送；`/api/send` 新增 `paths` 数组并保留旧 `path` | `windows-gui/src-tauri/src/main.rs`（`WindowEvent::DragDrop`）、`web.rs`（PAGE + `send_paths_from`）、`sendjob.rs`（`SendRequest.paths`） |
| 2c | 禁止第二个程序启动 | 应用数据目录 `desktop.lock` 上 `File::try_lock`，拿不到锁即 `exit(0)`；进程崩溃由系统释放，不留僵尸锁 | `windows-gui/src-tauri/src/main.rs`（`acquire_single_instance`） |
| 2d | 修复托盘右键一闪就没 | 原来任何按键（含右键、按下）都会 `open_ui` 抢焦点；改为只认 `MouseButton::Left + MouseButtonState::Up`，并设 `show_menu_on_left_click(false)`：左键开页、右键出菜单 | `windows-gui/src-tauri/src/main.rs` |
| 3a | 手机接收后记录消失，要点通知栏才显示 | 前台 1 秒轮询里检测「接收中→收完」跳变，立即刷新「最近接收」；原来只有 `onResume/refreshAll` 会扫目录 | `TcController.java`（`wasReceiving` / `refreshRecvProgress`） |
| 3b | 「最近接收」点条目用默认应用打开 | 根因是 URI 构造把已编码路径再转义一次（`appendPath(Uri.encode(...))`），`openFile` 解出的路径多一层转义，必然 `FileNotFound`。改为 `appendQueryParameter("p", abs)`，MIME 先查系统 MimeTypeMap 再退回猜测；无匹配应用时明确提示而非静默失败 | `FileServeProvider.java`、`TcController.java`（`openReceived`） |

## 2 顺带清理的漂移（原先待拍板项，已自行决定）

1. **版本**：`Cargo.toml` / 桌面 `Cargo.toml` / `tauri.conf.json` 同升 `1.4.1`；`README.md` 与 `docs/README.md` 的版本行改对（原来 1.4.0 说「三端仍 1.3.1」）。
2. **daemon 启动日志**：删掉「管理页需要令牌 / `?t=<令牌>`」提示（v1.3.0 起已改密码登录），改为「已启用密码登录」。
3. **CLI 退出码 3/4**：变体保留（映射与单测在），但**没接线**；注释改成「预留，未接线」并加 `#[allow(dead_code)]`，不再声称已生效。`EXPECTED_NAMES` 收进 `cfg(test)`，构建不再有 dead_code 告警。
4. **`hash_cache` 默认值**：桌面首启仍为 `true`（与 1.4.0 一致，不动既有用户配置）。理由：它只影响扫描速度与「size+mtime 未变但内容变了」的漏传面，本次需求不涉及；改默认会让老配置与新装机行为不一致，风险大于收益。
5. **`tc recv` 明文无门禁**：保留为排障入口，未改（改动会破坏现有排障脚本）。
6. **测试稳定性**：`tests/e2e.rs` 的 discovery 用例端口 `53318→53399`（本机常驻 daemon 的回环公告会覆盖同键），并加注释。
